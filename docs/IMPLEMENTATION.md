# KuberWeaver prototype implementation plan

> For Hermes: use subagent-driven-development, test-first slices and spec then security review.

Goal: a functioning self-hosted infrastructure portal, not a mock dashboard, using the supplied GNS3 project as the real deployment backend.
Architecture: FastAPI core with SQLite durable state and a serialized job worker, declarative local Git plugins, a React/Vite/React Flow portal, Ansible execution and OpenTofu where verified. Local-only control plane, external client data directory with private permissions. Do not alter source brief files or original application workloads.
Stack: Python 3.12+, FastAPI/Pydantic, SQLite, Git, Ansible, React/TypeScript/Vite/React Flow. OpenBao integration and authenticated local credential bootstrap. No paid services or external LLM required.

## User correction: Hermes-like modularity is an acceptance gate
The microkernel owns only identity/RBAC, persistent jobs/audit, approval policy enforcement, extension registry and event dispatch. Infrastructure, execution, secrets, notifications, diagnostics and service blueprints are replaceable providers. No vendor-specific if/else in the core. All extension code is trusted host code, not sandboxed merely by manifests. Third-party packages installed disabled; admin must explicitly trust and enable. Do not run uploaded code automatically.

SDK owner creates backend/kuberweaver/extensions.py (no __init__.py ownership). Contract: ExtensionRegistry() with register(kind:str,name:str,provider:Any,description:dict|None=None), get(kind,name), list(kind=None)->list[dict], emit(event:str,payload:dict)->list[dict], add_hook(event,handler), load_directory(path:Path, enabled:set[str]|None=None)->list[dict]. Duplicate registrations fail, invalid extensions isolated. Python package entrypoint register(ctx) where ctx is capability-limited registration context (not security sandbox); plugin.yaml id,version,entrypoint:'module.py',capabilities:list; paths contained no symlink escape; disabled plugins not imported; errors reported without breaking valid peers. Registry is configured in core with built-in read-only GNS3 inventory provider, diagnostics provider, notifications outbox, secrets provider, generic Ansible executor, and catalog blueprints. Optional providers have explicit availability metadata. Trusted extensions may register hooks before_plan/after_approval/job_started/job_finished; safety gates cannot be disabled by extension hooks.

Declarative blueprint discovery remains plugins/*/manifest.yaml, JSON Schema-driven UI, no core changes for a new compatible blueprint. Executor dispatch must use a registry/provider interface or generic manifest-driven Ansible execution, never plugin_id branching. Add external example extension examples/extensions/lab-notes with register(ctx) and a diagnostic provider/hook; parent proves disabled imports absent, enable registration works, deactivation no longer exposes capability. CLI at scripts/plugins.py list/doctor, optional enable/disable via persisted config. User configuration, plugin durable data and state outside shipped package.
